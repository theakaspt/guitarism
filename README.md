# Guitarism

기타 연주자를 위한 이론 참고 + 연습 웹앱. 디코더(5도권) · 코드 사전 · 스케일 세 화면과, 어느 화면에서나 계속 도는 251 잼 반주로 이뤄져 있다.

- 앱 주소(새 배포): Vercel 연결 후 여기에 적기
- 앱 주소(예전): https://theakaspt.github.io/guitarism/
- 개발 기록: [`docs/`](docs/) 폴더 (1부 · 2부 · 3부 · 4부)

## 처음 한 번만 하면 되는 준비

### 1. 프로그램 두 개 설치

**Node.js** — 앱을 내 컴퓨터에서 돌려보고 배포용 파일로 만드는 도구다.
<https://nodejs.org> 에서 **LTS**라고 적힌 버튼을 눌러 받고 설치한다. (버전 18 이상이면 된다.)

**GitHub Desktop** — 이미 쓰고 있는 그 프로그램. 코드 저장·업로드를 담당한다.

### 2. 저장소를 내 컴퓨터로 가져오기

GitHub Desktop에서 `File → Clone repository` → `theakaspt/guitarism` 선택 → 저장할 위치를 고르고 `Clone`.

### 3. 부품 내려받기 (한 번만)

터미널(맥은 `터미널`, 윈도우는 `PowerShell`)을 열고, 방금 클론한 폴더로 들어가서:

```
cd 클론한폴더경로
npm install
```

몇 분 걸린다. `node_modules`라는 폴더가 생기는데, 이건 GitHub에 올라가지 않는다(올릴 필요 없다).

> GitHub Desktop에서 `Repository → Open in Terminal`을 누르면 폴더 경로를 직접 칠 필요 없이 바로 그 폴더에서 터미널이 열린다.

## 매일 쓰는 흐름

### 내 컴퓨터에서 앱 켜보기

```
npm run dev
```

`Local: http://localhost:5173/` 같은 주소가 뜬다. 브라우저에 그 주소를 넣으면 앱이 뜬다.
**코드를 고치고 저장하면 브라우저가 알아서 바뀐다.** 끌 때는 터미널에서 `Ctrl + C`.

같은 와이파이의 아이폰에서 보고 싶으면:

```
npm run dev -- --host
```

`Network:` 옆에 뜨는 주소(예: `http://192.168.0.5:5173`)를 아이폰 사파리에 입력한다.

### 고친 게 멀쩡한지 확인하기

```
npm test
```

154개 남짓한 자동 검사가 돈다. **전부 초록색(passed)이어야 한다.** 하나라도 빨간색이면 그 부분을 고치기 전에는 올리지 않는 게 안전하다. 무엇을 검사하는지는 아래 "자동 검사" 항목 참고.

빌드까지 한 번에 확인하려면:

```
npm run verify
```

### 올리기 (= 배포)

1. GitHub Desktop을 연다. 바뀐 파일 목록이 보인다.
2. 왼쪽 아래 `Summary`에 무엇을 바꿨는지 한 줄 적는다. (예: `잼 시트 리듬 순서 변경`)

## Vercel에 처음 연결하기 (한 번만)

1. <https://vercel.com> 접속 → `Continue with GitHub`로 로그인.
2. `Add New… → Project` → `guitarism` 저장소 `Import`.
3. 설정 화면에서 확인만 하면 된다:
   - Framework Preset: **Vite** (자동으로 잡힌다)
   - Build Command: `npm run build`
   - Output Directory: `dist`
   - Root Directory: 비워 둠
4. `Deploy` 클릭. 끝나면 `guitarism-....vercel.app` 주소가 나온다. 그 주소를 아이폰 사파리에서 열고 `공유 → 홈 화면에 추가`.

이후로는 `Push origin`만 하면 자동으로 새 버전이 올라간다.

### 앱이 예전 화면 그대로일 때

이 앱은 오프라인에서도 열리도록 파일을 폰에 저장해 둔다(PWA). 새 버전이 올라오면 앱 아래쪽에 **"새 버전이 준비됐어요 → 새로고침"** 알림이 뜬다. 그걸 누르면 최신으로 바뀐다.

알림을 놓쳤다면 앱을 완전히 껐다 켜면 된다. 잼이 도는 중에 화면이 저절로 새로고침되면 반주가 끊기기 때문에, 일부러 자동으로 바꾸지 않고 물어보게 해 뒀다.

│  │  ├─ jam.js          잼 폼·컴핑 보이싱·리듬 타임라인
│  │  └─ tips.js         화면별 꿀팁 + 용어 미니 사전

│  ├─ components/        공용 화면 부품 (세로휠, 탭바, 에러 화면 등)

**색을 바꾸고 싶다** → `src/theme.js`
**화면 글자를 바꾸고 싶다** → `src/screens/` 안의 해당 파일
**소리를 바꾸고 싶다** → `src/audio/`
**기억할 설정을 늘리고 싶다** → `src/storage.js`의 `useStored` 사용 (아래 참고)
**음악 데이터(코드·스케일)를 바꾸고 싶다** → `src/theory/` (바꾼 뒤 반드시 `npm test`)

## 손대면 안 되는 규칙 (지난 사고에서 나온 것들)

1. **음악 데이터·계산을 고치면 반드시 `npm test`를 다시 돌린다.**
2. 음이름은 `ROOTS`(관례 표기)와 `noteName`(조성 인식) 두 가지만 쓴다. ♯만 쓰는 배열을 새로 만들지 않는다.
3. 소리 엔벨로프에서 `gain.value`를 **읽어서** 다음 값을 정하지 않는다. (지속 노이즈의 원인)
4. 모든 소리는 `master(c)`를 거친다. 스피커에 직접 연결하는 곳은 `context.js` 한 군데뿐이다.
5. 잼 스케줄러는 `JamProvider` 안에 둔다. 화면 쪽으로 옮기면 탭을 옮길 때 반주가 끊긴다.
6. 여러 마디짜리 리듬의 `h.b`는 패턴 전체 기준 박이다. 마디 거르는 계산을 건너뛰지 않는다.
7. 훅(`useEffect` 등)은 그 안에서 쓰는 변수를 선언한 **뒤에** 놓는다.
8. 잼 스케줄러의 `skipPast`를 지우지 않는다. 없으면 폰을 잠갔다 돌아올 때 밀린 소리가 한꺼번에 터진다.
9. 글자 크기를 11px 아래로 내리지 않는다. (`tests/a11y.test.jsx`가 막는다)
10. 버튼을 새로 만들면 `aria-label`을 붙인다. 아이콘만 있는 버튼은 화면 낭독기로 읽히지 않는다.
11. 글자 크기와 여백은 `src/theme.js`의 `FS`·`SP`에서 고른다. (아래 "디자인 규칙" 참고)
12. 금색은 "지금 선택된 것"과 "루트음"에만 쓴다. 동작 버튼은 `ACTION`을 쓴다. 코드톤 강조는 teal 계열로 분리돼 있다.
13. 잼 스케줄러의 `skipPast` 안에서 `st.loops`를 올리지 않는다. 폰을 잠갔다 돌아올 때 템포가 확 뛴다.
14. 팁을 새로 쓰면 그 내용이 맞는지 검사부터 만든다. (`tests/tips.test.jsx` 참고 — 이미 틀린 팁 세 개를 잡았다)

자세한 배경은 `docs/기타앱개발보고서1.md`, `docs/기타앱개발보고서2.md`, `docs/기타앱개발보고서3.md` 참고.

## 연습 도구

잼 시트를 펼치면 아래쪽에 **연습** 구역이 있다.

**카운트인** — 시작 전 한 마디(4박)를 스틱 소리로 세어 준다. 기타를 잡을 시간이 생긴다. 반주가 도는 도중 키를 바꿔도 다시 세지 않고, 재생 버튼을 새로 눌렀을 때만 나온다.

**기타 반주** — 끄면 드럼만 남는다. 그게 메트로놈이다. 소리만 꺼지고 **화면의 코드 표시는 계속 따라가므로**, 코드를 눈으로 보며 직접 치는 연습에 쓰면 된다.

**템포 올리기** — 목표 BPM과 증가폭(+2 또는 +5)을 정해 두면 루프가 두 바퀴 돌 때마다 조금씩 빨라진다. 목표에 닿으면 멈춘다. BPM 슬라이더를 직접 만지면 자동으로 해제된다(사람이 우선).

## 코드톤 타겟 뷰

스케일 화면에서 잼을 돌리면, 지금 울리는 코드의 구성음이 지판 위에서 밝아지고 나머지는 흐려진다. **가이드톤(3·7음)은 이중 테두리**로 한 번 더 표시된다. "표시" 줄 오른쪽의 `코드톤 강조` 버튼으로 끌 수 있고, 잼이 멈춰 있으면 예전 화면과 똑같다.

## 꿀팁

각 화면 아래에 지금 보고 있는 것에 맞는 한 줄이 뜬다. 눌러서 펼치면 보충 설명과 용어 풀이가 나오고, ✕로 닫으면 앱을 다시 켤 때까지 그 팁은 안 보인다.

팁 내용은 전부 앱 데이터로 검산한 것만 넣었다. 새 팁을 추가하려면 `src/theory/tips.js`에 넣고, **그 내용이 맞는지 확인하는 검사**를 `tests/tips.test.jsx`에 함께 넣어야 한다.

## 설정을 기억하게 만들기

앱은 마지막에 보던 탭, 잼 설정(키·폼·리듬·음색·드럼·BPM), 코드 사전 선택, 스케일 선택을 기억한다.
기억할 항목을 늘리려면 `useState` 대신 `useStored`를 쓰면 된다.

```js
import { useStored, intIn, oneOf } from "../storage.js";

// 이름, 기본값, 검사기
const [root, setRoot] = useStored("scale.root", 9, intIn(0, 11));
const [view, setView] = useStored("scale.view", "all", oneOf(["all", "box", "diag"]));
```

**검사기는 꼭 붙이자.** 나중에 목록이 줄어들면(예: 스케일 13종 → 10종) 저장해 둔 옛 번호가 범위를 벗어나 화면이 죽는다. 검사기가 그런 값을 버리고 기본값으로 돌려준다.

`localStorage`를 직접 부르는 코드는 `src/storage.js` 안에만 있다. 나중에 클라우드 저장으로 바꿀 때 이 파일만 갈아끼우면 된다.

**일부러 저장하지 않는 것:** 잼이 재생 중이었는지(앱을 켜자마자 소리가 나면 놀라니까), 포지션 번호(스케일을 바꾸면 어차피 처음으로 돌아간다).

## 디자인 규칙

값을 눈대중으로 정하지 않도록 `src/theme.js`에 척도를 박아 뒀다. 새 화면을 만들 땐 여기서 고르면 된다.

```js
import { C, FS, SP, ACTION } from "../theme.js";

<div style={{ fontSize: FS.body, padding: SP.md, gap: SP.sm }}>
```

**글자 5단계** — `FS.label` 11(작은 라벨) · `FS.small` 13(설명) · `FS.body` 15(본문·버튼) · `FS.strong` 19(코드 이름) · `FS.title` 30(화면 제목). 다이얼 가운데 키 글자(46)만 예외다.

**여백 5단계** — `SP.xs` 4 · `SP.sm` 8 · `SP.md` 12 · `SP.lg` 16 · `SP.xl` 24. 전부 4의 배수다. 실선 두께처럼 아주 얇은 것만 2px을 허용한다.

**금색(brass)은 "지금 선택된 것"과 "루트음"에만.** 누르면 뭔가 하는 버튼(듣기·보기·잼 시작)은 `ACTION`(회색 배경 + 흰 글자)을 쓰고, 그 버튼이 활성 상태가 됐을 때만 `ACTION_ON`(금색)으로 바꾼다. 이렇게 해야 화면에 금색이 보일 때 "저게 선택돼 있구나"가 바로 읽힌다.

이 규칙들은 `npm test`가 검사한다. 척도를 벗어난 값을 쓰면 빨간색으로 잡히고, 어디가 문제인지 파일·줄 번호까지 알려준다. 값이 흐트러졌다 싶으면:

```
node tools/design-pass.mjs           # 뭐가 어긋났는지 보기만
node tools/design-pass.mjs --write   # 실제로 정리
```
