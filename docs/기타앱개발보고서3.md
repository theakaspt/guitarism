# 기타 이론 앱 — 개발 보고서 3부 (v45 → Vite 이관)

**목적:** 1·2부(단일 `.jsx` 파일 + 수동 번들 시절)에 이어, 세 번째 작업 세션에서 진행한 **프로젝트 재구성(Phase 0)** 의 결정 지점·이슈·검증 방법을 검토·수정 담당자에게 전달.
**대상:** `guitar-theory-app.jsx` 단일 파일 → Vite + React 프로젝트
**이 세션의 범위:** 작업지시서 **Phase 0(이관)만**. 기능·디자인 변경 없음.
**완료 조건:** "화면과 소리가 지금 배포본(v45)과 동일함"

---

## 1. 이 세션의 범위

작업지시서 §4의 Phase 0에 한정했다. Phase 1(설정 영속·ErrorBoundary·스케줄러 견고화 등)과 Phase 2(UI/UX)는 손대지 않았다. 발주자와 합의한 진행 방식이 "이관이 끝나기 전에는 기능·디자인 변경을 섞지 않는다"였기 때문이다.

| 영역 | v45 → 이번 |
|---|---|
| 소스 | 단일 `guitar-theory-app.jsx` 1,827줄 | `src/` 아래 22개 모듈 |
| 빌드 | esbuild 수동 실행 → 파일 수동 업로드 | `npm run build` (Vite) |
| 배포 | GitHub Pages 웹 UI 업로드 | Vercel 자동 배포 (push하면 끝) |
| PWA | `sw.js` 캐시명 손으로 변경(`guitar-theory-v45`) | `vite-plugin-pwa`가 빌드마다 자동 생성 |
| 테스트 | 채팅 환경에만 존재, 저장소에 없음 | `tests/` 8개 파일 40개 검사, `npm test` |
| 문서 | 보고서 2개만 | README(비개발자용) + 보고서 3부 + 이관 대조표 |
| 언어 | JS | **JS 유지** (발주자 선택) |

## 2. 진행 순서

1. 저장소 클론 → 보고서 1·2부 정독 → 소스 1,827줄 구조 파악
2. 최상위 선언 블록 파서를 만들어 **모든 줄이 정확히 한 블록에만 속하도록** 분해 (누락·중복 0줄 확인)
3. 블록을 목표 모듈에 배치. **본문은 한 글자도 고치지 않고**, 선언 줄 앞에 `export`만 붙임
4. 예외적으로 `Scales` 컴포넌트 안의 순수 계산 3개만 파일 밖으로 이동(§3-3) → **6,708건 전수 대조로 결과 동일 확인**
5. Vite 프로젝트 구성 + `vite-plugin-pwa`
6. Vitest 테스트 8종 작성
7. **v45 배포 번들과 새 빌드의 화면 HTML 대조**(9개 화면, 완전 일치)
8. README·보고서 작성

## 3. 주요 고민 지점 & 결정

### 3-1. 새 버전 알림: 자동 새로고침 vs 물어보기

작업지시서는 `vite-plugin-pwa`의 **autoUpdate + 토스트**를 권했다. 그런데 autoUpdate는 새 버전을 감지하면 **화면을 알아서 새로고침한다.** 이 앱은 잼 반주가 계속 도는 앱이라, 연습 도중에 화면이 새로고침되면 소리가 끊긴다.

→ `registerType: "prompt"` + **"새 버전이 준비됐어요 → [새로고침] [나중에]"** 알림으로 결정. 지시서가 원한 결과("캐시명 수동 변경 절차를 완전히 대체")는 그대로 달성하면서, 새로고침 시점만 사용자가 고르게 했다. 알림은 새 버전이 실제로 올라왔을 때만 나타나므로 평소 화면은 v45와 동일하다.

### 3-2. React StrictMode를 켜지 않음

Vite의 React 템플릿은 기본으로 `StrictMode`를 켠다. StrictMode는 개발 모드에서 이펙트를 **일부러 두 번 실행**해 문제를 드러내는 장치인데, 이 앱은 잼 스케줄러가 이펙트 안에 있어(절대 규칙 5) 개발 중에 반주가 잠깐 두 겹으로 예약될 수 있다. "지금 배포본과 동일하게"라는 이관 원칙에 어긋나므로 켜지 않았다.

→ Phase 1에서 스케줄러를 견고화할 때 다시 검토할 것. (`src/main.jsx`에 이유를 주석으로 남겨 뒀다.)

### 3-3. `Scales` 안의 계산 3개만 파일 밖으로 뺀 이유

분할 원칙은 **"이동만, 수정 금지"** 였다. 딱 한 군데 예외를 뒀다. `Scales` 컴포넌트 안에 `build3nps`(3음/줄), `diagFrom`(대각선), CAGED 위치 계산이 **클로저로** 들어 있었는데, 이 상태로는 작업지시서 §4-3이 요구한 `theory-scales.test`(3nps 756개, CAGED 서명, 대각선 프렛 유효성)를 **실제 코드에 대고** 검사할 수 없다. 테스트가 같은 계산을 베껴 쓰면 "테스트와 앱이 따로 노는" 상태가 된다.

→ 본문은 그대로 두고 **클로저로 읽던 변수(`root`, `ivset`, `N`)만 인자로 바꿔** `theory/scales.js`로 옮겼다. 그리고 원본 클로저를 그대로 복사한 참조 구현과 **전 스케일 13종 × 12루트 × 전 시작위치 = 6,708건**을 대조해 결과가 완전히 같음을 확인했다.

### 3-4. ErrorBoundary는 Phase 1로 미룸

작업지시서 §4-1의 목표 구조에는 `main.jsx`에 ErrorBoundary가 적혀 있지만, 같은 문서 §5-2에서 폴백 화면 문구("문제가 생겼어요")와 "다시 시작" 버튼까지 Phase 1 항목으로 명세돼 있다. 절반만 지금 만들면 Phase 1에서 다시 뜯어야 하고, 이관 단계에서 화면 요소를 늘리지 않는다는 원칙에도 어긋난다.

→ **Phase 1에서 명세대로 한 번에** 만들기로 하고 이번엔 넣지 않았다. (발주자에게 보고 완료)

### 3-5. 서비스워커 폴백 범위

예전 `sw.js`는 실패한 **모든 GET**에 `index.html`을 돌려줬다(자산 요청에도 HTML이 감 — 지시서 §5-6이 지적한 문제). 새 설정은 `navigateFallback`을 화면 이동 요청에만 적용한다. `tests/dist.test.js`가 빌드된 `sw.js`에 `NavigationRoute`가 들어 있는지 확인한다.

### 3-6. 이관 전 원본을 저장소에 남김

`docs/legacy/`에 이관 직전의 `guitar-theory-app.v45.jsx`와 `bundle.v45.js`를 넣었다. 이유는 두 가지다. ① 전수 대조표(`npm run inventory`)와 v45 화면 대조(`npm run compare:v45`)를 **언제든 다시 돌릴 수 있게** 하기 위해. ② 이관 과정에서 뭔가 달라졌다는 의심이 들 때 원본을 바로 열어 볼 수 있게 하기 위해. Phase 1에서 화면을 바꾸기 시작하면 `compare:v45`는 당연히 달라지므로, 평소 `npm test`에서는 건너뛰도록 해 뒀다.

## 6. 알려진 한계 / 리스크 (갱신)

- **Vercel 연결은 발주자가 직접 해야 한다.** 저장소 push 권한이 이 작업 환경에 없어 코드는 로컬 폴더로 전달했고, GitHub 업로드와 Vercel 연동은 README의 절차대로 발주자가 진행한다. **실기기(아이폰) 확인은 그 이후에만 가능하다.**
- **화면 대조는 JSDOM 기준이다.** HTML 구조·글자·인라인 스타일이 완전히 같음은 확인했지만, 실제 픽셀 렌더와 **소리**는 실기기 확인이 필요하다. 소리 쪽은 코드가 한 줄도 바뀌지 않았다는 점(전수 대조)이 근거다.
- **GitHub Pages 배포본은 그대로 둔 상태다.** 발주자 결정에 따라 Vercel 확인이 끝난 뒤 정리 방법을 다시 논의한다. 그때까지 두 주소가 공존하며, Pages 쪽은 예전 v45가 계속 뜬다.
- **설정 비영속은 그대로다.** localStorage 저장은 Phase 1 항목이라 이번에 넣지 않았다. 앱을 껐다 켜면 여전히 초기화된다.
- **`_row` 상수는 쓰이지 않는다.** 원본에도 쓰이지 않던 죽은 코드지만, 전수 대조에서 "사라진 선언"으로 잡히지 않도록 `theme.js`에 그대로 옮겨 뒀다. 정리는 Phase 1 이후에.
- **`docs/legacy/` 가 저장소 용량을 약 340KB 차지한다.** 대조 재현을 위한 의도적 보존이다. Phase 1이 끝나 화면이 달라지면 `bundle.v45.js`는 지워도 된다.

## 8. 검토 시 유의점 (1·2부에 추가)

1. **분할된 파일 사이를 옮길 때도 전수 대조표를 돌릴 것** — `npm run inventory`. 이슈 #7의 재발 방지 장치다.
2. **`theory/`와 `audio/`는 React에 의존하지 않는다.** 이 경계를 유지해야 테스트가 화면 없이 계산만 검사할 수 있다.
3. **v45 대조(`npm run compare:v45`)는 Phase 0 전용이다.** Phase 1에서 화면을 바꾸기 시작하면 실패하는 게 정상이다. 그때부터는 참고용 기록으로만 본다.
4. **테스트에 박힌 숫자(414 · 1,872 · 756 · 106)는 "지금 규모"의 스냅샷이다.** 데이터를 의도적으로 늘렸다면 숫자를 갱신하고, 의도치 않게 바뀌었다면 원인을 찾을 것.
