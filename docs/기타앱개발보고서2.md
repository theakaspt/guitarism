## 1. 이 세션의 범위

1부가 "기능 골격 완성"이었다면, 이 세션은 **(a) 잼의 공용화·UI 재구조화, (b) 잼↔스케일 이론 연동, (c) 소리 품질(음색·리듬·밸런스) 대개편, (d) 실기기 배포(PWA)**를 다뤘다.

| 영역 | v13 → v45 변화 |
|---|---|
| 251 잼 | 디코더 내 패널 → **전역 미니 플레이어**(탭 이동에도 무중단 루핑) · 명칭 "251 잼 세션" |
| 컴핑 | 단순 스트럼 → **드롭2류 보이싱 + 보이스 리딩**(멜로디 이동 최소화, 2패스 루프 이음새) |
| 리듬 | 차알스턴 1종 → **컴핑 4종**(2마디 보사노바 클라베 포함) · **드럼 6종** |

## 3. 새 아키텍처 요소

| 항목 | 내용 |
|---|---|

| **JamBar** | 탭바 위 얇은 미니 바(키·폼·▶/■·teal 재생점) ↔ 탭하면 시트(세로휠 5개: 키·폼 / 리듬·음색·드럼 + BPM). App에 1개 상주 |
| **VWheel / WheelPicker** | 세로/가로 스냅 휠. `touchAction: pan-y` + `overscrollBehavior: contain`으로 페이지 스크롤 충돌 방지. JSDOM 가드(`scrollTo` 부재 대응) |
| **compCandidates / voiceProgression** | 인접 4현(A-D-G-B / D-G-B-E) 4음 보이싱 후보 생성 → 멜로디(톱) 이동 가중 2.0 + 시작 음역 앵커(top≈67) + **2패스**(마지막 코드 씨앗 재선택)로 루프 이음새 처리 |
| **jamTimeline** | 컴핑+드럼 이벤트 병합. **다마디 리듬 주기**(`bars`, h.b는 패턴 전체 기준 박) + **베이스 분리**(`bass:true` 히트 = 낮은 2음) 지원 |
| **음색 계층** | 기타 = 카플러스-스트롱(`ksBuffer`, FIR 루프필터 + `readDelay=period-(1-a)` 위상보정 → 오차 <1센트) / 로즈 = FM / 비브라폰·오르간 = 가산 합성 |
| **master(c)** | 모든 출력이 마스터 버스 → DynamicsCompressor(thr -6dB, ratio 12) → destination. **`c.destination` 직결은 master 내부 1곳뿐** |
| **PWA** | `pwa/`: index.html(iOS 메타·safe-area) + bundle.js(iife, minify) + manifest + sw.js(캐시 `guitar-theory-v45`) + icon 180/512 |

## 4. 주요 고민 지점 & 결정

1. **잼을 어디에 둘 것인가.** 두 탭에 큰 블록으로 중복 배치 → 화면을 잡아먹고 상태도 분리됨. → **미니 플레이어(전역 상주)**로 결정. 음악 앱의 관용 패턴이라 학습 비용도 낮음.

2. **휠 UI의 적용 범위.** 사용자가 세로휠을 원함 → 처음엔 "폭 부족·스크롤 충돌" 우려로 반대했으나, 폭 우려는 과대평가였음을 인정. **제스처 충돌만 CSS로 방어**하고 실기기 확인을 조건으로 진행 → 성공. (교훈: 추측으로 막지 말고 만들어서 실기기로 확인)

3. **잼↔스케일 연동의 복잡도.** 초기 구현(코드별 칩 상시 + 점수 + 대안 제안)이 "굉장히 복잡해졌다"는 피드백 → **"화면은 두 줄, 깊이는 접기"**로 재설계. 이후 B안(잼 카드 제거, 미니바에 안내)을 시도했으나 **맥락 없는 판정 문구**("이 스케일과 안 맞음")가 더 혼란 → 롤백 후 **C안(선택한 스케일 ↔ 251 잼 세션 대칭 카드)** 확정. (교훈: 정보를 줄이는 것과 맥락을 없애는 것은 다르다)

4. **스케일→잼 매칭 기준.** "스케일이 코드 구성음 4개를 전부 포함"으로 잡았더니 **펜타·블루스가 전멸**(156개 중 72개 후보 없음) — 실전과 어긋남. → **"스케일이 진행의 키(조성)에 속하는가"**로 교체, 블루스는 블루노트 2개 예외. 156개 전 조합 매칭 성공.

5. **코드별 스케일의 문맥성.** 단순 코드타입→모드 매핑은 마이너 251의 V7을 믹솔리디안으로 잘못 안내(나란한 단조와 충돌). → **폼의 조성 문맥 반영**: 마이너 폼 V7 = 하모닉 마이너(♭9·♭13), VI7 = 세컨더리 도미넌트 주석. 264개(6폼×12키×코드) 전수 검증.

6. **% 표기 vs 말.** "몇 % 통함" 요청에 **반대 의견 제시** — %는 분모가 불명확하고 행동으로 이어지지 않음. → **"전부 통함" / "E7만 주의 — G♯ 없음"**처럼 문제 지점을 콕 집는 방식으로 합의.

7. **음색 전략.** 어쿠스틱 피아노는 신스로 불가능(정직하게 반대), 대신 **신스로 정직하게 예쁜 것**만 추가: 로즈(FM)·비브라폰(가산+모터 트레몰로)·해먼드 오르간(드로바 가산). 기타 2종은 물리 모델 유지하되 **어쿠스틱 = 바디 공명 + 더블 스트링**, **일렉 = 픽업 + 진공관 + 캐비닛**으로 정체성 부여.

8. **볼륨 밸런스의 기준.** 피크 기준 dB 계산으로 두 번 실패(사용자 귀와 불일치) → **RMS(체감) 기준** 인정하고 재조정. 키운 볼륨의 클리핑 위험은 낮추는 대신 **마스터 리미터**로 해결. (교훈: 심리음향은 계산보다 귀가 우선, 단 안전장치는 계산으로)

9. **배포 경로.** Netlify Drop(익명 업로드는 임시) vs GitHub Pages → 지속 업데이트 전제라 **GitHub Pages** 선택. 웹 UI만으로 업로드 가능하게 안내(비개발자 제약 유지).

## 6. 검증 방법론 (추가분)

1부의 (A) 음악 로직 전수 검증 + (B) JSDOM 렌더 검증에 더해:

- **(C) 잼 지속 테스트** — 가짜 AudioContext(스케줄 카운터)로 "시트에서 ▶ → 탭 전환 2회에도 스케줄 증가 → ■ 후 증가 0" 확인. 하네스는 delay/waveshaper/compressor/detune까지 폴리필.
- **(D) 이론 연동 전수 검증** — 코드별 스케일 264개(스케일이 코드음 포함), 역방향 매칭 156개(후보 존재), 나란한조 재정렬 12키, 표기 일치 12키.
- **(E) 오디오 안전 검사** — `gain.value` 읽기 패턴 정적 검사, 엔벨로프 릴리스 전후 연속성 시뮬레이션, FM 순간주파수 양수, 드로바 합·동시 타격 합 클리핑 검사, 새츄레이션 배음 DFT.
- **(F) 리듬 타임라인 검증** — 다마디 주기 분배(마디별 히트 수), 박 범위, 보이스 유효성, 셋잇단 뒷박 위치.
- **(G) PWA 렌더 검증** — 번들 실행 + 300ms 후 DOM 내용·버튼·3탭 존재 확인.

- **PWA 업데이트 캐시:** 파일 교체 후에도 옛 버전이 뜰 수 있음 — sw.js의 캐시명(`guitar-theory-v45`)을 버전마다 바꾸고, 안내(아이콘 재추가/새로고침) 필요.
- **iOS 무음 스위치:** 웹오디오가 하드웨어 스위치에 막힘(1부와 동일, 해결 불가 — 안내로 대응).
- **설정 비영속:** localStorage 금지 제약 유지 중 — 실제 앱화 시 복원 예정이나 현 PWA도 미적용(껐다 켜면 초기화).
- **아티팩트 프리뷰 vs PWA 이중화:** 소스는 `.jsx` 하나지만 배포는 번들 재생성 필요 — 수정 시 **빌드→업로드 절차**가 추가됨.
- **음량 밸런스:** RMS 근사 기반이라 기기 스피커에 따라 체감 차이 가능.

## 8. 남은 작업 / 권장 사항

- **실사용 피드백 수집** ← 현재 단계. 배포본으로 연습하며 개선점 목록화.
- **잼 "보이싱 보기"** — 재생 중인 드롭2 보이싱을 지판에 표시 + 가이드 톤(3·7음) 강조 (계산은 이미 존재, 표시만 필요. 학습 기능 1순위).
- **코드톤 스케일 뷰** — 현재 코드의 코드톤 타겟 강조, 잼 연동.
- **기타 리듬 추가 검토** — 발라드(온음표)·삼바 등 (드럼은 6종으로 확장 완료).
- **디자인 패스 2차** — 간격·폰트 척도 통일(4의 배수·4~5단계), HANDOFF 갱신.
- **배포 운영** — 업데이트 절차 문서화(빌드→업로드→캐시명 변경), 필요시 Vite 프로젝트 이관.

## 9. 검토 시 유의점 (요약, 1부에 추가)

1. **음이름은 `ROOTS` 단일 배열**(관례 표기)과 `noteName`(조성 인식)만 사용 — ♯전용 배열을 다시 만들지 말 것 (이슈 #8).
2. **오디오 엔벨로프에서 `x.gain.value`를 읽어 스케줄하지 말 것** — 반드시 명시적 값으로 연속 스케줄 (이슈 #9).
3. **모든 오디오 출력은 `master(c)` 경유** — `c.destination` 직결 금지 (이슈 #10).
4. **렌더 테스트는 접힌 UI를 펼쳐서** — 토글·아코디언 안쪽이 사각지대 (이슈 #7).
5. **잼 스케줄러는 JamProvider 안에** — 탭 컴포넌트로 옮기면 무중단 루핑이 깨짐.
6. **다마디 리듬의 `h.b`는 패턴 전체 기준 박** — 마디 필터링(`hBar`) 로직을 우회하지 말 것.
7. 배포본 수정 시: esbuild 번들 재생성 → GitHub 업로드 → **sw.js 캐시명 변경**.
