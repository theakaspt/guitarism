# 기타 이론 앱 — 개발 보고서 (v13)

**목적:** 이 앱을 검토·수정할 담당자에게 개발 과정, 주요 결정(고민) 지점, 발생한 이슈와 해결, 검증 방법, 알려진 한계를 전달하기 위한 보고서.
**대상 파일:** `guitar-theory-app.jsx` (단일 React 파일)
**현재 버전:** v13

---

## 1. 제품 개요

기타 연주자가 이론이 막히거나 까먹었을 때 즉시 참고하고 연습하는 **레퍼런스 + 연습 웹앱**. 하단 탭 3개로 구성된다.

| 탭 | 핵심 기능 |
|---|---|
| **디코더** | 돌리는 5도권 다이얼 · 다이어토닉 코드/조표/나란한조 · 추천 코드 진행 · 251 재즈 잼(컴핑 루프) |
| **코드 사전** | 루트×타입×베이스(슬래시) 선택 · 세로 지판 운지(오픈/바레/트라이어드/탑4현/슬래시) |
| **스케일** | 13개 스케일 · 도수/음이름 · 4가지 보기(전체/포지션(CAGED)/3음퍼스트링/대각선) |

**1차 사용자:** 기타 경력이 오래됐으나 이론에서 자주 막히는 연주자(기획자 본인). 코딩 지식 없음. 이 제약이 개발 방식 전반을 규정했다(전문용어 최소화, 한 번에 하나씩, 실용 우선).

**참조 제품(기능만 참고, 그래픽 복제 안 함):** Noisy Clan Decoder(5도권), eapy(코드 사전 세로 지판 방식), Instagram @andres.ague(익스텐디드 펜타토닉).

## 2. 개발 진행 요약 (버전별)

작업은 **한 번에 한 기능**, **계획 → 승인 → 제작 → 검증 → 저장점** 사이클로 진행됐다.

- **v1–v3** 디코더: 5도권 다이얼 → 부채꼴 터치 개선 → 추천 코드 진행 + "이어가기" 확장
- **v4** 통합: 두 화면을 하단 탭 바로 묶음(스케일 자리 포함)
- **v5** 코드 사전 v1(오픈 코드 12개) → 통합
- **v6** 코드/스케일 "깊이 더하기": 코드 13타입(오픈+바레+트라이어드+탑4현), 스케일 13종
- **v7** 소리 재생(코드/스케일/진행) + 코드 지판 인레이·프렛번호
- **v8** 스케일 포지션(박스) 보기
- **v9** CAGED 시스템(메이저·펜타) + 박스별 재생
- **v10** 3음퍼스트링(3nps) 보기
- **v11** 가로 스케일: 대각선(익스텐디드 펜타토닉, 이후 전 스케일·루트 시작으로 개선)
- **v12** 슬래시 코드 + 3단(루트×타입×베이스) 선택 + "(추천)" 표시
- **v13** 251 재즈 잼(컴핑 루프 + BPM)

## 4. 주요 고민 지점 & 결정

1. **3단 휠 도입 타이밍.** 사용자는 참조 앱의 루트×타입×베이스 휠을 원했으나, 커버리지가 오픈 코드뿐일 땐 "아무 조합이나 된다"는 휠이 빈 화면(막다른 길)을 만든다. → **커버리지(바레 등)를 먼저 채운 뒤 3단 선택을 도입**하기로 함(v12).

2. **스케일 라벨: 도수 vs 음이름.** 이명동음(D♯/E♭) 표기 논쟁을 피하고 박스 모양 학습에 유리한 **도수(R, ♭3 …)를 기본**으로, 음이름은 토글로. 음이름은 키에 따라 ♯/♭ 선택(단순화).

3. **CAGED 명칭 관례 충돌.** 교재마다 같은 박스를 다른 폼으로 부른다(예: 마이너 펜타 6번줄 박스를 E폼 또는 G폼). → 임의로 단정하지 않고 **"루트가 어느 줄에 있는지"(Deft Digits) 서명 기준**으로 통일, 사용자에게 "관례가 다를 수 있음" 명시. 위치 공식은 **전 루트 스크립트 검증** 후 채택.

4. **가로 스케일 정의(중대 재설계).** 처음 "대각선"을 두 줄만 쓰는 방식으로 구현했으나, 사용자가 참조 이미지(@andres.ague, Extended Pentatonic)를 제시 → **넥 전체를 사선으로 오르는 익스텐디드 방식으로 교체**. 이후 시작점이 오픈 근처라 실전성이 떨어진다는 피드백 → **3~12프렛 루트에서 시작**하도록 개선하고 ◀▶로 시작 위치 선택. "한 줄" 보기는 사용자 요청으로 제거.

5. **슬래시 "(추천)" 기준.** 두 폼(6/5번줄 베이스) 중 어느 것이 흔한지는 주관적이라, **객관적 "잡기 쉬움" 점수**(낮은 포지션·개방현 수·좁은 폭·뮤트 구멍)로 계산해 태깅하고, "절대적 규칙 아닌 가이드"임을 명시.

6. **251 컴핑 리듬.** 다양한 컴핑이 있으나 v1은 가장 상징적·단순한 **차알스턴(1박 + 2박 뒷박) 스윙**으로. 마디 배분은 재즈 표준(ii 1 · V 1 · I 2).

7. **UI: 스핀 휠 vs 칩.** 참조는 돌리는 휠이나, 모바일 정확도·속도를 위해 **칩 선택 유지**. "실제 스핀 휠" 룩은 최종 디자인 패스로 미룸.

8. **정확성 최우선 원칙.** 음악 로직은 예외 없이 **스크립트로 전수 검증한 뒤** 반영(사용자가 이론 오류에 민감·중요시).

## 5. 이슈 & 해결 (Issue Log)

| # | 증상 | 원인 | 해결 | 예방 |
|---|---|---|---|---|
| 1 | **앱 화면이 아예 안 뜸**(v13) | `useEffect`가 참조하는 `selected` 변수보다 **앞에** 선언되어 TDZ 오류. 문법 검사(esbuild)는 통과해 못 잡음 | 이펙트를 `selected` 정의 **뒤로** 이동 | 큰 변경 후 **JSDOM 실제 마운트 렌더 테스트** 상시 실행 |
| 2 | 슬래시 코드가 오픈 폼을 못 잡고 높이 잡힘(Am/C 등) | 상단 줄 후보 프렛 창을 베이스 프렛 이상만 탐색 | 창을 `fb-3`까지 확장(상단 줄은 프렛이 낮아도 음정이 높음) | — |
| 3 | 일부 키에서 3nps/대각선 프렛 음수 | 시작 음이 너무 낮아 상위 줄이 개방현 아래로 내려감 | **시작 위치를 유효한 가장 낮은 자리로 보정** | 생성 후 프렛 0~15 유효성 검사 |
| 4 | CAGED 박스가 5폼과 깔끔히 안 맞음 | 6번줄 스케일음 앵커(6~7개)는 CAGED 5폼과 개수 불일치 | **루트-줄 서명 기반 5포지션 공식**으로 재정의, 전 루트 검증 | — |
| 5 | 초기 "대각선"이 의도와 다름 | 두 줄 방식 = 사용자가 원한 익스텐디드(사선) 아님 | 참조 이미지 확인 후 **익스텐디드 방식으로 교체** | 애매하면 참조자료·검색으로 사실 확인 후 구현 |

**첨언:** 이슈 #1은 "빌드는 되는데 화면은 안 뜬다"의 전형이다. 이후 **문법(esbuild) + 런타임(JSDOM 마운트 + 탭 클릭)** 이중 검증을 표준 절차로 삼았다.

## 6. 정확성 검증 방법론 (검토자 참고)

앱의 신뢰도는 두 축으로 담보했다.

**(A) 음악 로직 전수 검증 — Python 스크립트.** 실제 반영 전, 전 루트/전 타입에 대해 구성음·프렛 유효성을 계산해 확인. 대표 규모:
- 코드 운지 **258개**(오픈+바레+트라이어드+탑4) 구성음 일치 → 0 실패
- 슬래시 **1,872개 조합**(13타입×12루트×12베이스) 최저음=베이스 → 0 실패
- 3음퍼스트링 **756개**(9개 7음 스케일×12루트×7포지션) 줄당 3음·유효 프렛 → 0 실패
- 대각선/CAGED 위치 공식 → 전 루트에서 서명/음 일치 확인

**(B) 렌더 안전 — 빌드 + 실제 마운트.** `esbuild`로 문법을, **JSDOM에서 `createRoot().render(<App/>)` + 세 탭 클릭**으로 런타임을 검증(이슈 #1 이후 표준화).

## 7. 알려진 한계 / 리스크

- **음색:** 현재 심플 신스라 실제 기타/재즈 컴핑 질감은 아님(→ "리얼 음색" 작업 예정).
- **배포 안 됨:** 앱이 이 대화(아티팩트) 안에서만 렌더됨. "설치되는 진짜 앱"은 별도 배포 단계 필요. 원본 코드는 `.jsx` 파일이 유일 소스이므로 **백업 보관 필수**.
- **CAGED 명칭:** 채택한 관례가 일부 교재와 다를 수 있음(의도된 선택, 문서화됨).
- **음이름 이명동음:** 키별 ♯/♭ 단순화라 엄밀한 조성 표기와 다를 수 있음(위치는 항상 정확).
- **고프렛 클리핑:** 일부 키의 대각선/바레 폼이 15프렛 밖으로 나가는 경우가 있어 표시가 잘릴 수 있음.
- **보기 옵션 증가:** 스케일 "보기"가 4종(+선택기)으로 늘어 UI가 다소 빽빽함(디자인 패스에서 정리 권장).
- **접근성/반응형:** 다양한 화면·스크린리더 대응은 아직 미검증.

## 9. 검토 시 유의점 (요약)

1. **모든 음악 데이터는 계산·검증됨** — 임의 수정 시 반드시 전수 검증 스크립트를 다시 돌릴 것.
2. **색은 `C` 팔레트 한 곳** — 리컬러는 여기만.
3. **훅/이펙트는 참조 변수 선언 뒤에** — 이슈 #1 재발 방지.
4. **변경 후 JSDOM 마운트 테스트** 필수 — "화면 안 뜸"은 문법 검사로 안 잡힘.
5. 아티팩트 제약(**localStorage 금지, 인라인 스타일**) 유지.
